## 轮播图更新后丢失（架构性 bug）

- 根因：`FileService.CarouselPath` 指向**安装目录** `AppBasePath/Assets/Carousel`；MSI `<MajorUpgrade>` 大版本升级会覆盖/清除安装目录内属于安装包的文件（含默认 Carousel_1~5.png），用户自定义轮播图一并被清。应用实际装在 `C:\Program Files (x86)\YangzaiWorkshop`，扫描确认该目录只剩 5 张默认图，自定义图已不可恢复（被重置为默认）。
- 修复：把 `CarouselPath` 改到**用户数据目录** `App.WorkRoot/Assets/Carousel`（即 WorkData 下，不在 MSI 文件表，升级永不被清理）；新增 `SeedCarousel()` 一次性迁移旧安装目录的图并补齐默认图（幂等，仅目标为空时复制）。在 `HomePage.LoadBanners` 与"添加轮播"处理里调用 `SeedCarousel()`。编译通过（0 警告 0 错误）。
- 注意：头像 `profile.png`（AppBasePath/Assets/Avatar）同样在安装目录，存在相同升级丢失风险，暂未改（用户未反馈），后续可考虑一并迁移到 WorkData。
- 验证：实际运行新构建的 Release 版，`SeedCarousel` 正确把 5 张图从 `Assets/Carousel` 迁移到 `WorkData/Assets/Carousel`。用户"还是没有轮播图"的根因是跑的是旧编译产物（Debug 未重建），已重建 Debug。用户开发环境在 `bin/Debug/net8.0-windows/`（含真实 WorkData），应用未实际安装（`C:\Program Files (x86)\YangzaiWorkshop` 已不存在，只剩失效的开始菜单/桌面快捷方式）。

## 🔴 真因：MSI 把 Assets 文件夹"吃掉"了（轮播不显示的最终根因）
- 用户坚持"assets 根本没打进 msi"。反编译当前 MSI 后证实：文件**在**包里，但**目录层级被拍平**——`<Files Include="..\publish\Assets\**">` 把 `Assets` 段吞掉，图实际装在 `INSTALLFOLDER/Carousel/Carousel_1.png`，而应用读的是 `INSTALLFOLDER/Assets/Carousel/Carousel_1.png` → 找不到 → 不显示。Debug 能跑只是因为 csproj 把 `Assets/` 原样复制进 bin。Avatar/Icon 同样被拍平（应用读 `Assets/Avatar`、`Assets/Icon` 也会失效）。
- 试过 `SubDirectory="Assets"` 属性 → **WIX0004 非法属性**（此 WiX v7 版本 `<Files>` 无 SubDirectory）。
- ✅ 最终修复（Product.wxs）：在 `INSTALLFOLDER` 下显式声明 `<Directory Id="AssetsFolder" Name="Assets">`，并把 Assets 文件移入独立 `<ComponentGroup Id="AssetsComponents" Directory="AssetsFolder">`（`Files Include="..\publish\Assets\**"`），Feature 里加 `<ComponentGroupRef Id="AssetsComponents">`。反编译确认层级恢复为 `INSTALLFOLDER/Assets/Carousel/...`、`/Avatar/...`、`/Icon/...`。
- 同时**按用户"别那么复杂"的要求，移除 SeedCarousel 迁移逻辑**：删除 `FileService.SeedCarousel()`，简化 `HomePage.LoadBanners`（直接读安装目录 `Assets/Carousel` 默认图 + `WorkData/Assets/Carousel` 用户图，去掉 try/catch 包裹的迁移步骤），移除"添加轮播"里的 SeedCarousel 调用。
- 验证：decompile 确认层级正确；`dotnet publish -c Release` + `build.ps1 -SkipPublish` 重新生成 MSI（12:16，12.5MB）；实跑发布版 exe，`error.log` 为空、`Assets/Carousel` 5 张图正常读取。
- ⚠️ 教训：WiX v5/v7 的 `<Files Include="..\x\**">` 会**吃掉 glob 的固定前缀目录**，需要层级时必须用显式 `<Directory>` 元素，而不是 SubDirectory 属性（该属性不存在）。
